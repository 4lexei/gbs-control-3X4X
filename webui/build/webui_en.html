Color and filter profile
This firmware remembers the color and filter settings for each console separately (only if it has its own profile; I am working on it). Tapping SAVE stores them for the next time you use it, and they become its global setting.

If a particular game needs other settings (for example, the typical horror game so dark you can't see a thing), don't save here! Save a personal preset for that game in the MODE tab; that preset carries its own colors and filters and won't change the console's global setting.

sync_problem
Sync (sources that won't lock)
Experimental block to repair the atrocious sync of the ODV-II transcoder (composite to component) when using the PC-Engine. Of no use to other users.
  • For sources with weak or troublesome sync (for example, composite converted to component), where the picture jumps every couple of seconds.
  • Tolerant sync: a dropout shorter than about 0.9 s only freezes the picture. The preset is kept and the recovery steps that cause the jump are held back (raising the SOG level, rewriting the coast, freezing and unfreezing). If the signal is really lost, normal recovery still works. Off by default; remembered.
  • SOG +/- changes the level at which sync is sliced. With a weak or noisy sync tip, another level often holds where the current one fails; it also repeats the phase search.
  • SyncWatcher stops and starts the watching. While it is stopped nothing is detected (a console change will go unnoticed), and the status bar shows it with “watcher off”.
  • Auto-lock does by itself what you would do by hand: it stops the watcher as soon as the picture reads stable. The button steps through the lock points (off, 2, 10, 30, 62 stable readings): the later, the more settled the picture, so try the highest one it reaches.
  • While it counts, the watcher stays out of the way: no dynamic adjustments, no SOG optimization, no phase search, because on a weak source that disturbs the picture and resets the count to zero. That is why the higher points were hard to reach.
  • SyncWatcher also works as “try again”: releasing the watcher releases the coast, phase and clamp with it, and the count goes back to zero, so a new attempt never inherits the previous state. There is a short pause before it can lock again. If it still isn't right after several attempts, reload the preset to start as clean as possible.
  • Auto-retry makes the attempts for you: it releases the locked state after a few seconds and the next attempt comes by itself. Watch the picture and, as soon as it looks right, press “capture sync”: the attempts stop and that state is saved for this console's profile.
  • Everything in this block only acts on a console profile that has a saved state (or while auto-retry is looking for one), so a console that already works stays exactly the same.
  • While a saved state is in use, recovery no longer overwrites the pulse ignore or the coast, which is what spoiled it on every attempt.
  • The saved state is written again after every preset load, and “load sync” writes it again at any time. It holds the SOG level, the coast and whether it was left unfixed, the pulse ignore and the phase: what a weak or troublesome source needs and what the watcher would otherwise have to search for from scratch.
  • The ODV recipe writes the state that was measured working with the PC Engine through an ODV transcoder (SOG level 14, coast 16/256 unfixed, pulse ignore 51), as a starting point instead of nothing. It is not a guarantee: capture it if the picture comes out right.
  • Sync info writes the current sync state to the log, to compare settings while you try them.

VTotal toggle_off
Output frequency
  • Needs the external clock generator (Si5351). Without it, these options do nothing.
  • Follow the source: the output runs at exactly the console's frequency (for example, 59.82 Hz with the PC Engine).
  • 59.94 Hz / 60.00 Hz: the output stays at a standard frequency (50 Hz sources stay at 50 Hz). Useful with capture cards that don't accept odd frequencies. In these modes FrameTime Lock can't follow the source, so a tear line may slowly travel across the picture.
  • Exact: the output runs at the figure you type (for example 59.8245). If the console is more than 1.5 Hz away from it, the output follows the console. As with 59.94 and 60, FrameTime Lock does not act.

Developer
Clocks
  • ADC clock (PLLAD_MD): how many samples the chip takes per console line. It is the “PLL divider++” above, but with the exact figure. It changes live; loading a preset puts it back. Careful: some values cut the wifi (it happened to me with 1784 on the PAL Mega Drive).
  • Output clock (Si5351): the one that sets the output Hz. Useful to look at and to experiment; the output rate steering and FrameTime Lock may move it again.
  • Tearing line: “FTL phase” moves the point where FrameTime Lock places the output against the input (90° from the factory), and the tearing line with it. “Reset memory” restarts the picture memory without reloading the preset. Neither is saved.

Sharpness
Peaking level—
Raising sharpness artificially creates white halos and makes noise more visible. Blurry signals sometimes benefit, though it will depend on your taste. Try it and decide.
Edge level—
Sharpens color changes: color is processed with less detail than brightness and tends to bleed at the edges. More level leaves cleaner transitions, but if you overdo it color outlines appear next to the edges. Try it and decide.
Deinterlacing
Only acts on interlaced sources (480i / 576i). Motion Adaptive removes the flicker, with some artifacts on what moves. Bob adds no delay and can be combined with scanlines, but it flickers.
Noise
Cleans noise from the signal before digitizing it. Probably unnoticeable with 240p sources. Not tested with VGA and above.
